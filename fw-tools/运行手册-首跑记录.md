# fw-run 操作手册 & 脚本化现状（2026-08-21 首跑记录）

> 目标达成情况：framework-v1 已从"代码库"变成"可调用的程序"——`fw-run 任务目录` 一把梭。
> 本文记录：怎么用、哪些已脚本化、哪些还差（下一步做什么才能像 lh 一样顺手）。

## 一、现在就能用（已脚本化，3 条命令）

```bash
# 1. 一键跑（demo=链路联调 0token / codex=真实LLM干活）
fw-run 任务-xxx_日期 --mode codex --max-parallel 2

# 2. 实时看状态（事件驱动，非轮询）
fw-status 任务-xxx_日期             # 跟随
fw-status 任务-xxx_日期 --once      # 一眼

# 3. 断点续跑
fw-run 任务-xxx_日期 --resume
```

**脚本资产**（`framework-v1/`）：
| 文件 | 作用 |
|---|---|
| fw-tools/fw-run.sh | 一键启动（→ 挂成 `fw-run` 命令） |
| fw-tools/fw-status.py | 状态查看器（→ 挂成 `fw-status` 命令） |
| fw-runner/bin/fw-executor.sh | executor 包装器（demo/codex/dsh 三模式） |
| fw-runner/bin/fw-auditor.sh | auditor 包装器（demo/llm 两模式） |

### 首跑真 executor 踩坑（三连环 bug，2026-08-21）

1. **UnicodeDecodeError**：headless 被包装器杀掉时 session 正在 stream 中文输出，stdout 截断出半个多字节 UTF-8 → runner `subprocess.run(text=True)` 解码炸 → 修复 `errors="replace"` + `except UnicodeDecodeError` 兜底
2. **`ROUND: unbound variable`（全角括号黏连）**：`$ROUND）` 中文右括号无空格，bash `set -u` 把 `ROUND）+` 当变量名 → "agent 非零退出(1)" 0.25s 秒败 → 修法：所有 `$VAR中文` 改 `${VAR}中文`
3. **交付说明不填**：executor 只写代码不写文档 → ① 指令强调"交付说明是凭证不填视为未完成" ② 包装器检测占位符自动补录
4. **src/.gitkeep 误判产物**：find 排除 .gitkeep/demo-output.txt/空文件

**教训**：bash 脚本里变量后紧跟全角/中文标点是定时炸弹（`set -u` 下有 strict 解析差异）；agent 输出被 kill 时的截断流必须有 errors=replace 兜底。


### 第二次真跑踩坑（补）

5. **substance 字段丢失 → 心跳守护误判 stall**：executor outcome 写了 `"substance": true`，
   但 `DriverOutcome.from_mapping()` 不解析 substance（保持 None）→ runner 退回指纹判定 →
   第二轮起产物无变化（覆盖同名文件）→ 指纹不变 → "连续2轮无实质产出" 误判 → 3 模块回人。
   修复：from_mapping 补 `if "substance" in d: o.substance = bool(d["substance"])`
   （这是框架补丁级 bug，不是 executor 问题）

6. **auditor 升级为 dsh headless 真验收**（fw-auditor.sh）：读任务书 acceptance + 产物 + 交付说明 →
   headless 只读审计 → 输出 VERDICT=/ROOT=/CONF=/REASON= 四段 → 解析成 DriverOutcome。
   与补丁2 的 _valid 校验对齐（verdict∈{pass,block}、root 合法、confidence∈[0,1]）。


### 第三次真跑踩坑（auditor 超时真因 = 任务污染）

7. **auditor 超时无判定 → 根因是审计任务被污染**：
   - 现象：manual 跑 auditor 150s 能 pass，runner 里 120-300s 全超时
   - 真因：`cat 交付说明.md` 把 runner 兜底的"已完成: executor 未落档进度"垃圾写进 AUDIT_TASK，
     任务又脏又长 → headless 处理不过来超时 → block(0.3 兜底) → 判断 loop
   - 修复：① 任务书只提取 objective+acceptance（python 瘦身，40 行 vs 上百行）
     ② 交付说明 grep -v 掉"未落档/runner兜底"占位 ③ 超时 180→300s
   - 验证：m01 判定 pass conf 0.97（比污染版 0.93 还稳）

8. **教训（重要）**：agent 任务的输入必须"干净且只含验收所需"——把中间产物/兜底日志灌进去
   会让 LLM 超时或判歪。给 agent 的信息是"信息按需投递"原则的实战验证。


### 第 N+1 次踩坑：进程管理（孤儿堆积）→ fw-spawn.py

9. **孤儿进程堆积**：`kill $JOB` 只杀 bash 包装器，**dsh headless 是 Node 子进程没被杀** →
   70+ 孤儿吃光资源 → 新 headless 起不来 → auditor/executor 全超时（26s 秒败）
10. **macOS 无 setsid**：改用统一 spawner `fw-runner/bin/fw-spawn.py`：
    - Popen 列表参数（**不走 shell**，防多行长文本/路径空格炸）
    - start_new_session=True 独立进程组；killpg 收 SIGTERM/SIGINT 时清理进程组
    - macOS killpg 限制 → PermissionError 忽略（清理目标已达成）
11. **shell 炸长文本**：`shell=True + 多行中文任务` → 被当多条命令 → 全部命令 not found。
    必须列表参数 + argv 传递，绝不能把任务文本粘进 shell 字符串。

**Executor/Auditor 架构定稿**：包装器 bash（读任务书/拼指令/写 outcome）+ fw-spawn.py（起 headless、进程组管理、超时清理）。这层解决"agent 子进程生命周期"通用问题，任何角色（executor/auditor）共用。


### 多层 audit 反复超时 —— 输出文件竞争

12. **首轮 4 模块 run 结果**：m01/m02 **done**（auditor 真验收 pass 0.95，m02 还把复核报告存了 tmp/auditor_output2.txt），m03 needs_human、m04 pending（auditor 反复"未输出 VERDICT"超时）。
13. **m03/m04 反复超时真因之一 = 输出文件竞争**：每轮 audit 都写同一个 tmp/auditor_output.txt，
    旧孤儿 spawn 的 headless 与新轮次的 headless 同时写 → 内容互相覆盖/混合 → VERDICT 行找不到。
    → 修复：输出文件改为带轮次后缀 auditor_output_${ROUND}.txt，互不干扰。
14. **教训**：agent 子进程的输出文件必须按轮次隔离（同文件并发写 = 竞态）。
    另外：run 结束后应 kill 所有 fw-spawn/headless 孤儿，否则累积吃资源（本轮 pkill 数次）。


### m03/m04 反复"超时"的真因（回家后第一个要修）

15. **m03 auditor 其实判了 pass，但没按严格格式输出**：
    - auditor_output_5.txt 2449 字节含完整结论（四条验收全过、confidence 0.9、"验收闭环完成，无阻塞项"）
    - 但**没有 `VERDICT=` 行** → 脚本 grep "VERDICT=" 找不到 → 判定"超时无判定" → 打回 → 5 轮耗尽 needs_human
    - 即：executor 写完了、auditor 也看完了，**只差格式**！
16. **修复方向**（回家做）：
    - ① 脚本对"没有 VERDICT= 但输出很长且含 pass/block"的审计结果做**智能兜底解析**
    - ② 或在指令里把输出格式再强化（"最后一行必须严格 VERDICT=xxx 且不能是多行/列表"）
    - ③ 或解析失败时把审计输出原文带进 blocker 给人看（现在信息黑洞）
17. **m04 同理待查**（大概率同样：有输出但无 VERDICT= 行）。
