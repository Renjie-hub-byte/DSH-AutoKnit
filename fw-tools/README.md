# fw-tools — 框架配套工具

## fw-status.py — 运行状态查看器（事件驱动，非轮询）

看任务跑到哪了：模块完成/在跑/回人、token 消耗、最近事件。

```bash
# 实时跟随（出个状态就展示，Ctrl+C 退出）
fw-status 任务-订单管道_2026-08-21

# 只看当前状态一次（不跟随）
fw-status 任务-订单管道_2026-08-21 --once

# 已归档的 run（自动下钻找 总日志/）
fw-status e2e/runs/run-xxx/archived/任务-xxx
```

### 设计：为什么不是轮询

- 任务进程把每一步写进 `总日志/dispatch.jsonl`（**追加写**）
- `fw-status` 跟随模式用 **seek 尾随**：每次只从上次读到的位置读新增行；
  无新增时在文件尾部**阻塞等待**（等价 `tail -f` 语义）
- 不产生无意义的重复读取；事件到了立刻渲染，事件没到就安静等着

### 能看到什么

- 整体状态：任务名 / run_id / 已用 token / 每个模块 ✅🔄⛔🙋
- 实时事件流：executor 开工/完成/出错、auditor 判定、模块完成/blocked、
  限流退避（module.env_backoff）、预算预警、集成验收
- 新增事件类型只需在 `EVT_LABEL`/渲染分支补一行

### 局限（诚实）

- 是终端的滚动状态流，不是 Web 仪表盘；无历史回放（-once 看最近 6 条）
- 对"等待你处理"（needs_human）会显示 🙋，但不会主动通知（没有通知机制）
- 若要 Web 可视化：后续可做 SSE 推送（读同一 dispatch.jsonl 增量播给浏览器）
