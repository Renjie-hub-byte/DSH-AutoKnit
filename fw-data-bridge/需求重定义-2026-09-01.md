# fw-data-bridge 需求重定义（2026-09-01，交给另一个 agent）

> 背景：数据桥 + 面板现在补丁一堆（有时有数据有时没有、刷新读取慢）。底层是架构问题——**要重写数据流，不要继续打补丁**。本文是需求清单（Owner拍板）。

## 代码位置
- 后端：`~/projects-hold/projects/dsh-workflow/framework-v1/fw-data-bridge/`（fwapi serve :8765）
  - `src/fwapi/dsh/usage.py`（token 聚合）、`registry.py`（run 注册表）、`serve.py`（HTTP）、`events.py`（事件推送）
- 前端：`dsh-client-ui-autoknit` 插件（autoknit-v2 工作区，面板）
- 工具：`fw-tools/fw-token.py`（按模块聚合 token，已支持 `--cwd` 单 run 隔离）

## 核心需求（Owner只需要这些，别的不做）

面板按 run 展示四块：

1. **总消耗**：该 run 的 input / output / cache_read / 计费（未缓存输入+输出）/ 总用时
2. **planner 消耗**：plan 阶段的 input / output / cache / 用时
3. **模块消耗**：每个模块（m01/m02/m03…）的 input / output / cache / 计费 / 用时 / 轮次
4. **run 切换**：多个 run 可切换查看
5. **归档**：run 可点击归档（归档后从列表消失 / 不参与统计）

## 数据源（各字段从哪来）
- dsh 会话 `~/.fw-dsh/sessions/`：per-session usage（inputTokens / outputTokens / cacheReadTokens）
- `总日志/快照.json`：模块/轮次/预算
- `总日志/dispatch.jsonl`：每轮 executor/auditor tokens + 时间戳（用时）
- `runs.json`（注册表）：run 列表 + 状态 + started_at
- planner 消耗：快照里没有单独记，需从 plan 阶段会话（planner session）聚合

## 已知问题（重写时要规避的，都是补丁留下的债）
1. **会话聚合串扰（BUG-009）**：按模块 id 聚合时把历史 run 同名模块会话串进来 → 已修（`--cwd` 限定），但聚合逻辑补丁味重
2. **缓存双计**：usage 归一化时缓存读重复计入
3. **刷新慢**：每次全扫所有会话 → 应事件驱动增量更新
4. **数据时有时无**：竞态（会话未写完就读）+ 路径/根不统一（~/.fw-dsh vs ~/.fw-dsh-bench 双根）
5. **归档逻辑**：归档 run 又会被事件驱动加回来（补丁多）

## 目标设计
- **单 run 隔离**：聚合必须限定在 run 任务目录（`--cwd` 语义），杜绝串扰
- **一次查询返回 run 摘要**：GET /api/runs/<id>/usage 一次返回 {run: {total, plan, modules[]} }，前端不再拼
- **事件驱动增量**：会话写入时增量更新，不每次全扫（参考 events.py 现有思路）
- **run 列表 + 归档持久化**：注册表加 archived 字段，列表/统计都过滤
- 双根统一：`~/.fw-dsh` 主根 + `~/.fw-dsh-bench` 遗留根，扫描逻辑收敛成一处

## 验收
- 面板显示：总/plan/模块 的 input/output/cache/计费/用时，正确对账（与快照 budget_used_tokens 精确一致）
- 多 run 切换正常
- 归档后从列表消失且不复活
- 刷新不卡（增量更新）
